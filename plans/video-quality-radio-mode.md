# 다중 화질 및 라디오 모드 지원 기획안

## 📊 기획 방향성 (UX & BM 고려)

### 1. UX (사용자 경험) 포인트
* **유연한 시청 환경 제공:** 사용자의 기기나 네트워크 상태에 맞춰 영상 화질(고/중/저)을 선택할 수 있어 버퍼링 없는 감상이 가능합니다.
* **라디오(오디오) 모드:** 화면을 보지 않고 음악/합주 소리만 듣고 싶을 때, 라디오 모드로 전환하여 불필요한 배터리 소모와 데이터 사용량을 줄입니다.

### 2. BM (비즈니스 모델 / 서비스 가치) 포인트
* **트래픽 비용 절감:** 기존처럼 무조건 원본 화질을 로드하는 대신 상황에 맞는 화질/오디오만 로드함으로써 스토리지 및 CDN 대역폭 비용을 최적화합니다.
* **사용성 개선을 통한 리텐션 방어:** 데이터 요금 부담이나 로딩 지연에 따른 유저 이탈을 방지합니다.

## 📝 개발 파트별 작업 지시서

### 🧑‍💻 [BE 개발자용 지시서]
복잡한 DB 테이블 구조 변경이나 새로운 인증 로직 추가는 불필요합니다. 기존 데이터 구조를 최대한 활용하세요.

* **API 응답 구조 개선:** 
  기존의 단일 영상 URL을 반환하던 엔드포인트 응답 규격을 확장해서, Cloudflare Stream이나 R2 버킷에 저장된 HLS 마스터 플레이리스트(.m3u8) URL 혹은 화질별(원본/720p/480p/오디오) 파일 URL 목록을 함께 반환하도록 수정해줘.
* **비즈니스 로직:** 
  영상이 업로드될 때 비동기로 저화질 및 오디오 전용 파일을 생성(트랜스코딩)하여 스토리지에 저장하는 가벼운 스크립트만 파이프라인에 추가해줘. 별도의 무거운 프레임워크나 DB 설계는 필요 없어.

### 🧑‍🎨 [FE 개발자용 지시서]
새로운 페이지 전체를 만들기보다, 기존의 비디오 재생 영역만 업그레이드하는 컴포넌트 단위 교체로 진행하세요.

* **비디오 플레이어 교체:** 
  기존 기본 `<video>` 태그 대신 다중 화질(HLS) 및 오디오 모드 전환을 매끄럽게 지원할 수 있는 라이브러리(예: `hls.js` 또는 `video.js`)를 연동한 커스텀 컴포넌트를 만들어줘.
* **UI/UX 구현:** 
  영상 컨트롤 바 하단에 '톱니바퀴' 아이콘을 배치하여 화질(고/중/저)과 라디오 모드를 직관적으로 선택할 수 있는 미니멀한 드롭다운 UI를 구현해줘. 로컬 상태 관리를 통해 변경 시 즉각 반영되도록 처리해줘.
