# 우선 보안 두 건과 밴드 대시보드 복원 계획

- 작성일: 2026-10-13 / 기준 HEAD: `c1c6ed4`
- 상태: 2026-10-14 구현·회귀 검증·단위별 커밋 완료. 브라우저 시각 검증은 접근 제한으로 미완료이며 운영 배포는 아직 하지 않음.
- 별도 보안/정책 대기열: [security-policy-backlog.md](security-policy-backlog.md).

## 목표와 범위

1. 보안 의존성 보완(Flask-CORS, Vite)과 공개 장소검색 남용 방지 두 작업을 먼저 처리한다.
2. 밴드 홈을 사진·달력·연습곡·최근 활동 중심으로 복원하고 계정/밴드 관리와 분리한다.
3. 기존 밴드 격리·공개 범위·계정 전환 경계를 유지한다. v1 화면/데이터 연결을 그대로 되살리지 않는다.
4. 법적 문구·연령·계정 삭제 정책은 별도 대기열로 관리하며 이번 UI 복원에 섞지 않는다.

## 구현 진행 기록 (2026-10-14)

- 계획·보고서 5개만 명시적으로 Git에 포함했다 (`85e0530`). 기존 docs 전체나 비밀 설정은 포함하지 않았다.
- Flask-CORS 6.0.2와 명시적 CORS 계약 (`e456925`), Vite 7.3.7 (`5f65fe5`) 갱신을 완료했다.

- 밴드별 dashboard 조회·SQL 집계·월 일정 페이지·기간 합주·공개 범위 검증을 완료했다 (`d724561`, 관련 테스트 19개 통과).
- 사진·달력·다가오는 합주·연습곡·최근 사진을 보여주는 조회용 홈을 복원했다 (`512a565`). 월 일정 더 보기와 일부 표시 안내, 서명 URL 1회 갱신, 권위 있는 v2 상세 조회, StrictMode 및 늦은 응답 차단 회귀를 포함한다.
- 소유자/관리자 대표 사진 설정 API를 별도 커밋했다 (`863e0d2`, 관련 격리 테스트 21개 통과).
- 관리 메뉴와 공지 공개 범위 편집·대표 사진 선택/해제를 기존 밴드 관리 화면으로 분리했다 (`845bff0`). 플랫폼 관리자 여부는 밴드 관리 권한을 대신하지 않는다. 저장 후 재편집, 권한 해제 403, 계정 전환, 사진 갱신/선택 경쟁을 검증했다.
- 전체 백엔드 격리 회귀는 667개 통과(기존 경고 903개, 약 7분 19초)했다. 테스트용 PostgreSQL 프로세스가 종료된 것을 확인했다. 최종 FE 회귀 181개와 변경 파일 ESLint, Vite 7.3.7 운영 빌드가 통과했다. 기존 500KB 이상 chunk 경고는 후속 성능 과제로 남긴다.
- 합성 데이터·SVG 이미지로만 구성한 로컬 샘플(PC/390×844 모바일 프레임)을 준비했다. 브라우저 도구가 localhost에 접근할 때 `ERR_CONNECTION_TIMED_OUT`을 반환했고, 로컬 Chrome 연결도 제공되지 않아 시각 검증은 미완료다. 샘플 서버는 검증 시도 후 정리하며, 공개 노출로 우회하지 않는다. 운영 환경 및 실제 기기의 시각·재생 검증을 완료했다고 주장하지 않는다.
- 이번 작업에서 운영 DB 변경, R2 쓰기·삭제, 영상 변환, push 또는 배포는 하지 않는다. 배포는 별도 승인 후 진행한다.
- 실제 자격정보가 담길 수 있는 backend `.env`는 읽지 않는다. 전체 테스트는 dotenv 로딩을 앱 import 전 차단하고 환경변수를 제거한 격리 환경 및 전용 localhost PostgreSQL fixture로 실행한다.

## 현재 코드에서 확인한 원인

- `frontend/src/components/workspace/BandWorkspace.jsx`의 BandDashboard는 곡/합주 목록 각 1건 요청의 pagination.total과 공지만 표시한다. 사진·월별 달력·상태별 연습곡 UI가 없고 현재 접근 권한 카드가 강조된다.
- 예전 `components/dashboard/Dashboard.jsx`에는 대표 사진, 곡 상태 요약, RehearsalCalendar가 남아 있다. 하지만 v1 fetchDashboardStats/fetchFeaturedImage, 전역 SongContext, 단일 밴드 명칭에 의존한다.
- v2 합주 목록은 날짜 오름차순 페이지 조회이며 월별 필터가 없다. 첫 페이지만 달력에 넣으면 월 일정이 누락될 수 있다. 곡도 전체 상태별 집계가 아닌 일부 페이지를 합산하면 오표시한다.
- 밴드 관리 `/bands/:bandSlug/manage`와 계정 `/bands`는 이미 존재한다. 관리 기능을 새로 중복 구현하기보다 기존 권한 화면을 확장한다.

## 화면·동선 분리

| 화면 | 경로 | 담당 내용 |
|---|---|---|
| 내 계정 | `/bands` | 프로필, 접근 가능한 밴드, 가입/생성 요청, 초대 코드 입력, Superadmin 메뉴 |
| 밴드 홈 | `/bands/:bandSlug` | 대표 사진, 공지 요약, 월별 달력, 다가오는 합주, 연습곡 요약, 최근 사진 |
| 밴드 관리 | `/bands/:bandSlug/manage` | 소유자/관리자의 가입 승인·초대 관리, 공지 편집, 대표 사진 설정 |
| 플랫폼 승인 | `/platform/band-requests` | Superadmin 전용 생성 승인. 밴드 홈이나 일반 관리 권한과 혼합하지 않음 |

- 기존 `/band/:bandSlug/...` 별칭은 유지하고 canonical URL은 현재 `/bands/:bandSlug/...`를 유지한다. 표시 이름 변경으로 주소를 자동 변경하지 않는다.
- 밴드 홈의 권한 통계 카드와 공지 인라인 편집은 제거/이동한다. 조회용 공지는 홈에 유지한다.
- 관리 메뉴는 서버 권한이 있는 사용자에게만 보인다. 직접 URL 접근은 기존 API/페이지 권한으로 차단한다. 일반 멤버의 곡·합주·사진 작성과 본인 콘텐츠 편집은 각 콘텐츠 화면에 유지한다.

## 밴드 홈 구성안

- 상단: 밴드 이름과 짧은 소개, 대표 사진. 임시 imported legacy 문구를 실제 소개로 자동 덮어쓰지 않고, 내용이 없으면 중립 안내를 표시한다.
- 주요 카드: 다가오는 합주(날짜·시간·장소·연결 연습곡), 공지 요약.
- 본문: 월 이동 가능한 합주 달력 + 선택 날짜의 일정 목록. 날짜뿐 아니라 시작일~종료일 범위가 그 달과 겹치는 합주도 표시한다.
- 연습곡: Practice/Completed/OnHold 상태별 정확한 수와 현재 연습중 곡 최대 5개. 점수는 미디어의 추천 점수이며 곡 자체 점수로 바꾸지 않는다.
- 하단: 최근 사진 최대 4개와 갤러리/곡/합주 화면 이동 링크. 영상 자동재생과 홈의 전체 미디어 목록 로딩은 제외한다.
- PC는 2열 카드, 모바일은 사진→다가오는 합주→공지→달력→연습곡 순의 1열. 사진은 가로세로 비율을 보존하고 불필요한 인물 잘림을 피한다. 대표 사진이 없으면 중립 placeholder를 쓰고 사진 없음/일정 없음/연습곡 없음 상태를 구분한다.
- 밴드별 로고·테마 색·사용자 커스터마이즈는 기존 추후 과제로 유지하고 이번 범위에 넣지 않는다.

## 데이터/API 계획

- 기존 featured-gallery/announcement v2 API와 serializer를 재사용한다. 새로운 공개 URL이나 R2 객체 복사를 만들지 않는다.
- 조회 전용 `GET /api/v2/bands/{bandId}/dashboard?month=YYYY-MM`를 추가하는 방향을 우선안으로 둔다. 정확한 상태 집계, 당월 일정, 다가오는 합주, 제한된 연습곡·최근 사진을 하나의 밴드 scope로 조회한다.
- 월 입력은 엄격 검증한다. 일정은 해당 월 날짜/기간 overlap 조건으로 DB에서 필터링한다. 첫 페이지를 전체 월 데이터로 오인하지 않도록 일정 페이지 계약과 더 보기/추가 로딩을 둔다. 다음 일정은 현재 날짜 이후 오름차순으로 별도 조회한다.
- 날짜는 기존 합주 날짜 문자열 계약을 유지하고 월/일 계산에 UTC 변환으로 날짜가 바뀌지 않게 한다. 현재 한국 대상의 오늘·다가오는 일정 기준을 명시하고 월 경계 테스트를 둔다. 향후 밴드별 timezone 설정은 별도 범위다.
- 모든 SQL은 중앙 band scope, 부모/자식 visibility 및 기존 graph 무결성 규칙을 적용한다. 집계에도 동일한 필터를 적용해 숨긴 콘텐츠의 존재나 건수를 누출하지 않는다. 잘못된 다른 밴드 ID는 404다.
- 응답 건수·문자열/이미지 목록을 제한하고 일정은 페이지 조회, 집계는 SQL로 한다. 전체 곡·합주·미디어를 브라우저에 내려받아 계산하지 않는다. 관계 eager loading으로 N+1을 피한다.
- 요약과 기존 목록 간 필터를 중복 작성하지 않도록 필요한 읽기 query helper만 추출한다. 기존 API 응답과 정렬 계약은 유지한다.
- 대표 이미지 서명 URL 만료 시 한 번 재조회하며, 이미지 실패가 달력과 연습곡을 숨기지 않게 한다. PUBLIC/MEMBERS TTL은 기존 정책을 그대로 사용한다.
- 밴드/계정 전환 시 요청 취소·결과 무효화·상태 초기화. 사용자/밴드/월 별 query identity를 사용하고 멤버 전용 응답을 다른 계정에 재사용하지 않는다.
- 달력 클릭은 선택 날짜 일정을 표시하고, 곡/합주 카드는 안전하게 해당 v2 상세를 연다. 기존 목록에 상세 선택 링크가 없다면 검증된 ID query/deep-link 계약을 별도 추가한다. 레거시 onSelectSong/global context를 연결하지 않는다.

## 실행 순서·담당·커밋

1. **BE 보안 의존성 계약·갱신:** 공식 릴리스와 호환성을 재확인, CORS 회귀 테스트를 먼저 보강, 필요한 pin만 갱신. 커밋: `Harden backend CORS dependency contracts`.
2. **FE Vite 최소 갱신:** 수정된 지원 7.x 및 lockfile 갱신, 전체 FE 테스트·build. 커밋: `Update Vite security patch release`.
3. **장소검색 보호:** 현재 FE 호출자 확인 → 인증/band 경로 계약 → 입력 상한/호출량/캐시/timeout 테스트 → BE 및 호출 FE 변경. BE/FE 커밋 분리. 쿼터 알림·공유 제한 저장소 등 공급자 설정은 필요 시 별도 승인 요청.
4. **대시보드 읽기 계약:** 두 밴드·다른 사용자·공개범위 테스트를 먼저 작성, 월 overlap/정확한 상태 집계/상한/쿼리 횟수를 검증, v2 dashboard API 구현. 커밋: `Add scoped band dashboard reads`.
5. **대시보드 UI 복원:** 조회 전용 컴포넌트(대표 사진/합주달력/다가오는 합주/연습곡/최근 사진)로 분리한다. 기존 react-calendar 패키지는 band-aware 입력을 받는 presentational 컴포넌트에서 재사용할 수 있다. 커밋: `Restore band activity dashboard`.
6. **관리 동선 분리:** 공지 편집·대표 사진 설정을 기존 관리 화면/갤러리 설정과 연결, 중복 관리 로직 제거, 메뉴·직접 접근 권한 검증. 커밋: `Separate band administration from dashboard`.
7. **전체 검증·배포 준비:** BE 전체 pytest는 자격정보를 제거한 격리 환경과 필요 시 전용 로컬 PostgreSQL로 실행. FE 전체 tests, 변경 파일 lint, 운영 build, PC/모바일 시각 검증. 외부 push·Fly/Cloudflare 배포는 별도 승인 범위를 확인한 뒤 수행.

실 구현은 요청하신 subagent 중심으로 BE/FE 범위를 분리하고 메인은 코드·테스트·권한·diff 검토와 취합을 담당한다. 단계 1→2→3의 보안 보완을 먼저 끝내고, 4 이후 대시보드 작업을 진행한다. 정책 사실 확인은 별도 병행 가능하지만 정책 미확정 상태에서 고지문을 자동 발행하지 않는다.

## 완료 기준

- 허용 frontend CORS는 유지되고 임의 origin/비정상 preflight는 허용되지 않는다. 의존성 수정 릴리스가 lock/빌드 산출물과 일치한다.
- 장소검색에서 과도한 요청은 제한되고 외부 호출 수가 bounded다. 정상 사용·빈 검색·upstream 실패에서 기존 폼이 깨지지 않는다. 다중 worker/재시작 한계가 문서화된다.
- 홈에서 현재 밴드의 사진·월별 일정·정확한 연습곡 요약을 확인할 수 있다. 관리자용 권한 카드·편집 폼이 홈을 지배하지 않는다.
- 0건·다수 페이지·기간 합주·월 경계·모바일·서명 URL 만료·권한 변경·밴드 전환에서 데이터 누락/혼합/누출이 없다.
- 기존 곡/합주/갤러리/업로드/미디어 추천·음원 재생은 유지된다. 데이터 migration, R2 쓰기/삭제, 영상 변환 및 높은 CPU 작업은 이 계획에 포함하지 않는다.

## 계획 단계에서 남겨두는 결정

- 장소검색의 외부 공개 소비자가 필요한지: 코드 호출자 조사 후 활성 멤버 전용 v2 전환을 우선안으로 제시한다. 기존 공개 기능을 몰래 끊지 않는다.
- 정책 문서 사실표의 운영자/연락처/공급자 기간은 별도 수집한다. 미확정 사항은 보안·정책 대기열에 보존한다.
- 요청한 계획·보고서 5개는 구현 시작 시 명시적으로 Git에 포함했다. 기존 docs ignore 정책은 유지하고, secrets·기존 문서 전체를 함께 stage하지 않는다.
