# 업로드 콘텐츠·개인정보·권리 보호 정책 계획

- 작성일: 2026-10-21
- 상태: 6단계 구현과 로컬 회귀 검증, 승인된 운영 DB v22 적용·읽기 전용 사후 검증, Fly BE v64 배포·운영 API 검증을 마쳤다. FE push·라이브 배포는 아직 완료되지 않았다. R2 국외 처리 위치·경로 확인과 최종 국외 이전 고지는 미확정이다. 2026-10-22 사용자 결정에 따라 Cloudflare 문의 없이 기술 변경을 먼저 배포하되 정식 정책 공표·필수 확인 활성화는 보류한다.
- 적용 대상: 국내 이용자 대상 무료 웹 서비스, 만 14세 이상. 설치형 앱·후원·유료 기능은 이 계획의 범위가 아니다.
- 관련 계획: [가입 소개·최소 고지·봇 방지](signup-introduction-policy-captcha.md), [밴드 탈퇴·콘텐츠 보존](band-leave-and-content-retention.md), [보안·정책 후속 과제](security-policy-backlog.md).
- 최초 요청은 계획 작성만 승인했으며 그 시점에는 구현하지 않았다. 이후 6단계 구현·검증·필요 배포와 이번 범위의 운영 DB 추가가 승인됐다. 2026-10-23 root가 전체 회귀 통과 뒤 신선한 읽기 전용 백업·소유 로컬 복원·기존 기록 보존 검증을 완료한 다음 승인된 운영 DB v22의 빈 테이블·인덱스를 적용했고, 새 읽기 전용 연결의 사후 검증도 통과했다. Fly BE v64 배포와 운영 HTTP/CORS·시작 로그 검증도 완료했다. 일반 `origin/master` push와 FE 배포는 아직 완료되지 않았다. 미확정 정책은 공표하지 않고 `ready=false`, `POLICY_SIGNUP_ENABLED=OFF`, `UPLOAD_POLICY_REQUIRED=OFF`를 유지한다. 비밀 설정 변경·실제 메일 발송·R2 쓰기/삭제·재변환 등 별도 승인 경계는 유지한다.

## 현재 결정·작성 상태

- 사용자 확정: **새 업로드는 MEMBERS 기본값**. 기존 공개 자료는 일괄 변경하지 않는다.
- 사용자 확정: 삭제가 확정된 개인정보가 운영자 보관 DB 백업에 남아 있으면 **삭제 확정 후 30일 이내** 정리한다. 현재 자동화는 없으며 [권리 요청 운영 절차](../policies/rights-request-runbook.md)의 운영자 수동 책임으로 실행·증빙한다. 공급자 백업·로그 전체에 같은 30일 보장을 확대하지 않는다.
- 사용자 확정: 업로드 확인 기록은 해당 콘텐츠가 유지되는 동안 보존하고 삭제 확정 후 30일 이내 정리한다. 계정 삭제 때 감사 기록의 개인 연결을 제거하거나 익명화한다. 문의·신고 처리 기록은 종료 후 30일 이내 정리하며, 진행 중인 분쟁이나 법정 보존에 필요한 최소 자료는 예외로 구분한다. 이 기준은 수동 운영 기준이고 이번 구현이 실물 삭제를 자동 실행하지 않는다.
- 확인된 운영 사실: Supabase는 Free 플랜이며 프로젝트 지역은 `ap-northeast-1`(Tokyo)이다. R2는 APAC 위치 안내와 **미완료 multipart 7일 후 abort** 규칙을 확인했다. APAC는 특정 국가 보장이 아니며, 7일 규칙은 업로드 완료 파일의 보관·삭제 기간이 아니다.
- 사용자 최신 확정(2026-10-22): [공급자 위치 확인](../policies/provider-location-confirmation.md)의 Cloudflare 문의는 이번 릴리스에서 생략하고 기술 변경을 먼저 배포한다. 실제 국가·관할 확인과 국외 이전 고지는 미해결로 남긴다. R2를 한국 전용 저장으로 가정하거나 그렇게 고지하지 않는다. 문의 초안은 참고 자료이며 발송하지 않았다.
- 2026-10-22 로컬 검증: 프런트엔드 345/345와 lint/build, 최종 백엔드 전체 회귀 1098개 통과·실패 0·건너뜀 0. FE `cea4d6e`, BE `4b5661b`, 운영 검증 도구 `40b755b`는 로컬 단위 커밋이다. [준비 보고](../reports/20261021-upload-policy-release-readiness.md)에 이전 실패와 수정 후 재검증 이력을 보존한다. Cloudflare의 실제 처리 국가·국외 이전 고지 자료는 여전히 확인되지 않았다.
- 2026-10-23 운영 검증: ledger whitelist 수정 커밋 `7d71302`의 helper 테스트 10개가 모두 통과했다. root의 읽기 전용 public 백업·로컬 복원·v22 리허설 및 조건부 운영 적용·새 읽기 전용 사후 검증이 모두 verified로 끝났다. 원본 37개 public 테이블(앱 36개+Alembic ledger)에서 새 38개 테이블로 넘어갔고, 새 제한 테이블은 0행이며 기존 기록 보존 검증을 통과했다. 비공개 증거 원문 대신 [준비 보고](../reports/20261021-upload-policy-release-readiness.md)에 해시만 기록한다. Fly BE v64를 배포해 `/api/v2/policy`·`/members`의 HTTP 200과 Pages origin CORS, 정책 필수 기능 OFF 및 시작 로그를 확인했다. FE push·라이브 검증은 아직 하지 않았다.
- 작성한 초안: [이용약관](../policies/terms-draft.md), [개인정보처리방침](../policies/privacy-draft.md), [업로드 핵심 안내·권리 확인](../policies/upload-rights-draft.md). 아직 정식 공표본이 아니다.
- 최종 법적 미확정: 공급자별 국외 이전 경로에 적용할 법적 근거, 실제 국가와 법정 고지 범위. R2의 APAC 안내를 특정 국가로 바꾸어 쓰지 않는다. 공급자 로그·백업의 실제 보유 등은 확인된 사실만 고지한다. 개인 Gmail 사용이나 DPA 미서명만으로 불법이라고 단정하지 않으며, 공급자 변경·DPA 서명·지원 문의 발송을 이 계획으로 실행하지 않는다. 미성년자의 행위에 필요한 법정대리인 동의와 개별 업로드의 권리 확보는 운영 시 확인할 의무이지 모든 이용자의 신분증 확인이나 모든 커버곡의 일괄 라이선스 확보를 정책 공표의 독립 조건으로 삼지 않는다.

## 1. 목적과 원칙

밴드의 합주·연습 기록을 저장하고 공유하는 데 필요한 범위에서 약관, 개인정보 고지, 업로드 권리 확인, 권리 침해 접수를 정리한다. 현재 서비스의 영상·음원·사진에 공통 적용하며 새로운 업로드 기능을 추가하는 계획은 아니다. 가입자 한 명의 확인으로 영상에 등장하는 모든 사람의 동의나 원곡 권리자의 허락을 대신했다고 보지 않는다.

- 업로더와 권리자는 자신의 권리를 유지한다.
- 서비스 제공에 필요한 이용허락과 개인정보 처리 근거를 구분한다. 개인정보처리방침 열람을 포괄적 필수 동의로 표현하지 않는다.
- 공개 범위에 맞는 허락을 확인한다. 촬영·밴드 내부 공유·인터넷 전체 공개는 같은 의미로 다루지 않는다.
- 무료·비영리·멤버 전용이라는 사정만으로 커버곡 또는 타인 콘텐츠의 이용이 허용된다고 보지 않는다.
- 일반 콘텐츠 삭제 권한과 개인정보·초상권·저작권에 관한 법정 권리 행사를 구분한다.

## 2. 문서별 범위

| 문서·접점 | 포함할 내용 | 피할 표현·운영 |
|---|---|---|
| 이용약관 | 서비스 목적의 제한적 콘텐츠 이용허락, 게시 책임, 공개 범위, 탈퇴 후 잔존, 신고·이의제기·서비스 조치 | 영구·무제한 이용허락, 모든 권리 양도, 모든 책임의 일괄 면제 |
| 개인정보처리방침 | 처리 항목·목적·법적 근거, 보유·파기, 권리 행사, 공급자 위탁·국외 처리의 실제 사실 | 개인정보 처리를 모두 하나의 필수 동의로 묶기, 확인하지 않은 기간·국가 공표 |
| 업로드 안내·권리 확인 | 영상 저장·변환·M4A 추출, 선택 범위의 재생·공유, 필요한 게시 허락 확인 | 업로더의 체크 하나가 제3자의 동의나 음악 이용허락을 만들어 준다는 설명 |
| 신고·삭제 요청 안내 | 비회원도 가능한 이메일 접수, 최소 본인·권리 확인, 적용 법률에 따른 처리·통지·이의제기 | owner가 동의하지 않으면 법정 권리도 행사할 수 없다는 설명 |

### 서비스 목적의 콘텐츠 이용허락

약관 초안은 **비독점적이며 서비스 제공에 필요한 범위의 이용허락**으로 작성한다. 업로드한 파일을 저장·백업하고, 재생 호환성·데이터 절약을 위해 압축·변환하거나 M4A 음원을 추출하고, 사용자가 선택한 공개 범위에서 전송·재생하는 데 필요한 행위를 구체적으로 적는다.

서비스와 무관한 홍보, 재판매 또는 AI 학습 권한을 이 조항에 끼워 넣지 않는다. 새로운 목적이 생기면 별도 정책·법적 근거와 필요한 이용자 선택을 검토한다. 종료·삭제 시 이용허락의 종료 범위와 백업 잔존 기간은 실제 파기 절차에 맞춰 정한다.

### 개인정보 고지와 필요한 동의

계정·멤버십·가입 이름·선택 소개, 사진·영상·음원의 식별 가능한 얼굴·목소리, 활동·보안 로그를 실제 처리 항목에 맞춰 분류한다. 각 처리에 계약 이행 등 적용할 근거가 있는지 검토하고, 동의가 필요한 처리라면 목적·항목·기간·거부 시 영향을 구분해 안내한다.

영상 속 타인에 관한 처리를 업로더의 약관 동의만으로 정당화하지 않는다. 얼굴·목소리를 서비스 기록에 포함하는 것과 민감정보·생체인식정보로 분석하는 것은 구분하며, 이 서비스가 하지 않는 분석을 하는 것처럼 고지하지 않는다. 영상 속 개인정보를 무기한 보유하는 데 포괄 동의시키지 않는다.

## 3. 이용자 확인 시점

| 시점 | 제안 동작 | 기록·적용 기준 |
|---|---|---|
| 회원가입 마무리 | 약관 확인과 만 14세 이상 자기확인, 개인정보처리방침 링크 | 승인된 버전과 확인 시각을 서버 기준으로 기록. 일반 가입자에게 생년월일 전체나 신분증을 일괄 수집하지 않음 |
| 최초 업로드 | 자동 처리·공개 범위·탈퇴 후 잔존·문의 방법을 짧게 안내 | 핵심 안내 버전 확인. 긴 본문은 링크로 제공 |
| 매 업로드 묶음 | 게시·공유 권한과 필요한 출연자·권리자의 허락을 확보했는지 확인 | 여러 파일에 같은 확인을 적용할 수 있게 하되 대상 파일과 밴드·공개 범위를 명확히 표시 |
| 전체 공개로 확대 | 비회원도 열람할 수 있음을 보여 주고 다시 확인 | 파일뿐 아니라 곡·합주 등 부모 공개 범위 변경이 실제 접근을 확대하는 경우도 포함 |

가입 확인은 해당 버전에 대해 한 번 받는 방향이며 매 업로드마다 긴 약관을 다시 확인시키지 않는다. 중요한 약관 변경의 재확인 필요 여부와 적용 방법은 변경 내용에 따라 별도로 검토한다.

**신규 업로드는 멤버 전용(MEMBERS)을 기본값으로 한다는 사용자 결정을 받았다.** 현재 코드에서 부모·밴드 설정을 상속하는 경로를 검토하여 새 업로드에 적용하며, 정책 문구만으로 이미 적용됐다고 설명하지 않는다. 기존 공개 자료를 일괄 비공개로 변경하지 않는다.

권리 확인 문구는 “이 파일을 선택한 범위로 게시·공유할 권한이 있고, 필요한 출연자·권리자의 허락을 받았습니다”라는 취지의 초안으로 시작한다. 저작권과 개인정보의 법적 근거는 같은 문장으로 해결됐다고 보지 않는다.

## 4. 구현할 때의 계약

### 프런트엔드

현재 파일 선택·드롭 후 즉시 전송되는 흐름을 **선택 → 파일·공개 범위·권리 확인 → 업로드 시작**으로 바꾼다. 여러 파일을 한 번에 확인할 수 있게 하고, 시작 전 취소·파일 제외를 제공한다. 곡·합주·개인 기록·갤러리의 적용 대상을 정리해 누락을 막는다.

부모의 멤버 전용 제한 등 최종 유효 공개 범위를 이해할 수 있게 표시한다. 전체 공개로 확대할 때는 이미 업로드한 콘텐츠도 외부에 보일 수 있음을 확인한다. 확인 중 밴드·계정·파일 묶음이 바뀌면 이전 확인을 그대로 재사용하지 않는다.

### 백엔드와 최소 확인 기록

클라이언트 체크 여부만 신뢰하지 않고, 서버가 현재 정책 버전·확인한 사용자·밴드·대상 업로드와 공개 범위를 검증한다. 기존 receipt 재사용 가능성을 먼저 확인하고, 구체적인 최소 구조와 보관 기간은 구현 설계에서 확정한다.

- 최소 필드: 확인 종류·버전, 사용자/밴드 식별자, 업로드 세션 또는 묶음 식별자, 확인 당시 공개 범위, 서버 확인 시각. 업로드 확인 기록은 해당 콘텐츠가 유지되는 동안 보존하고 삭제 확정 후 30일 이내 정리한다.
- 확인 증거를 위해 콘텐츠 원문, 전체 파일명 목록, 토큰, 서명 URL, 불필요한 IP·기기 지문을 일괄 저장하지 않는다.
- 완료 재시도는 멱등성을 유지한다. 같은 세션의 재시도로 확인 기록·미디어가 중복 생성되지 않게 한다.
- JWT 만료 뒤 이미 승인된 세션 capability·ACK·완료·취소 계약을 보존한다. 새 업로드 시작 시 필요한 확인을 검증하고, 완료 시 현재 가입 상태·유효 권한을 재검사하는 기존 경계를 유지한다.
- 승인된 빈 `content_restriction` 테이블·인덱스 추가는 사전 백업·로컬 복원·기존 데이터 보존 검증을 통과한 뒤에만 적용한다. 그 외 운영 DB 변경은 별도 범위 검토를 받는다.

현 `policy_service.py`는 cutoff 이전 계정의 가입 정책 확인을 면제한다. **기존 계정도 새로운 업로드 정책이 적용된 뒤 새 업로드를 시작할 때 필요한 확인을 받는 방향**으로 기존 면제 설계를 재검토한다. 기존 가입 기록을 위조·소급 생성하거나, 새 확인으로 과거 영상의 허락 문제가 해결됐다고 처리하지 않는다.

## 5. 탈퇴·계정 삭제·권리 침해 처리

### 일반 서비스 동작

- 밴드 탈퇴는 멤버십을 종료하고 공동 콘텐츠는 자동 삭제하지 않는 현 정책을 유지한다.
- 일반 화면의 콘텐츠 삭제 권한은 해당 밴드 owner와 플랫폼 superadmin에 둔다.
- 계정 삭제는 밴드 탈퇴와 별개다. 본인 확인 후 Auth 계정·로컬 사용자·작성자 연결·소유권·멤버십을 구분해 처리하고 감사 기록의 개인 연결은 제거하거나 익명화한다. 공동 기록 보존과 개인정보 삭제의 근거를 각각 검토한다.
- 계정 삭제를 콘텐츠 전체 자동 삭제 또는 모든 개인정보의 영구 보존으로 단순화하지 않는다.

### 권리 행사와 신고

비회원·탈퇴자·영상 출연자도 중앙 문의 이메일로 접근할 수 있게 한다. 이메일은 기존 중앙 연락처 설정을 재사용하여 나중에 한곳에서 바꿀 수 있게 한다.

1. 대상 밴드·게시물 URL 또는 식별 정보, 문제 사유, 원하는 조치, 답변 받을 연락처를 접수한다. 필요한 최소 범위에서 본인·권리 관계를 확인한다.
2. 개인정보 정정·삭제·처리정지, 명예·사생활 침해, 저작권 복제·전송 중단 등 요청 종류에 적용할 절차를 구분한다.
3. 법이 즉시 중단·삭제·임시조치 등을 요구하는 요청은 일반 검토 대기나 owner 승인 때문에 지연하지 않는다. 적용 요건·서류·통지·기간은 법률 검토에서 확정한다.
4. 검토 중 필요한 범위에서 임시 공개 제한·전송 중단을 하고, 요청자와 게시자에게 필요한 통지 및 이의제기 방법을 제공한다.
5. 재개는 게시자의 주장이나 owner 요구만으로 자동 처리하지 않고, 해당 법률의 재개 요건·기간·상대방 통지와 필요한 권리 확인을 따른다.
6. 결과와 최소 처리 이력을 남기고, 문의·신고 처리 종료 후 30일 이내 기록을 정리한다. 진행 중인 분쟁이나 법정 보존의 최소 자료는 예외로 구분하며, 삭제된 콘텐츠·백업·로그의 잔존 및 파기 범위를 실제 기준에 맞춰 안내한다.

“owner만 삭제할 수 있다”는 일반 UI 규칙을 법정 권리 행사 거절 사유로 쓰지 않는다. 개인정보·초상권·저작권 등 모든 신고에 동일한 법정 기간·임시조치 절차가 적용된다고 단정하지 않는다.

## 6. 공표 전에 결정·확인할 사실

- **최종 국외 이전 고지:** Supabase·Fly.io·Cloudflare·메일 공급자별 실제 이전 경로의 법적 근거·국가·법정 고지 범위. 국내 이용자만 받더라도 해외 인프라 사용 사실은 따로 검토하고 APAC를 특정 국가로 기재하지 않는다.
- **운영 사실 대조:** 원본·변환본·M4A의 실제 동작과 승인된 업로드 확인·계정 감사·문의 신고·운영자 백업의 보존 기준을 공표 문구 및 수동 정리 절차와 대조한다. 공급자 로그·백업 기간은 확인된 범위만 안내한다.
- **권리·연령 안내:** 업로드 자료별 필요한 권리와 미성년자의 행위에 필요한 법정대리인 동의를 안내한다. 업로더의 확인만으로 모든 권리 확보를 검증했다고 설명하지 않는다. 모든 커버곡의 일괄 라이선스나 모든 미성년자의 신분증 수집을 독립적인 공표 조건으로 두지 않는다.
- **적용·요청 운영:** 확정된 신규 MEMBERS 기본의 실제 적용, 기존 계정의 새 업로드 확인 시점, 기존 공개 영상의 권리 검토 방법, 신고 담당자·최소 확인 자료·임시 제한·통지·재개 기준과 대응 가능 일정. 지킬 수 없는 기한·자동 조치를 약속하지 않는다.

기존 영상에는 적법한 허락이 있다고 일괄 추정하지 않는다. 신고나 권리 불명확성이 확인되면 개별 검토하며, 일괄 삭제·공개 범위 변경은 이 계획으로 승인하지 않는다.

## 7. 단계별 진행안

1. **운영 사실·정책 결정:** 신규 MEMBERS 기본과 업로드 확인·계정 감사·문의 신고·운영자 DB 백업 보존 기준은 승인됐다. 최종 국외 이전 고지 범위를 확정하고 공표·설정 활성화 게이트는 별도로 유지한다.
2. **문서 초안:** 약관·개인정보방침·업로드 안내·신고 절차를 작성하고 서로 모순되는 보존·공개·삭제 표현을 정리한다. 법률 확정본으로 자동 공표하지 않는다.
3. **백엔드 계약과 중요한 회귀 검증:** 현재 버전·계정·밴드·업로드 묶음·공개 범위 확인, 권한 변경, 완료 멱등성·capability 호환을 검증한다. 기록 스키마의 필요성을 확정한다.
4. **프런트엔드 UX:** 선택 후 확인·시작, 첫 안내, 파일 묶음 권리 확인, 전체 공개 확대 재확인, 계정·밴드 전환과 취소를 구현한다.
5. **운영 요청 절차:** 이메일 접수·최소 권리 확인·임시 제한·통지·검토·재개·파기 안내를 담당자가 실제 처리할 수 있게 정리한다.
6. **기술 릴리스 준비:** 승인된 운영 DB 추가 전에 읽기 전용 백업·소유 로컬 복원·기존 기록 보존 검증을 완료한다. 실패하면 DB 적용과 그에 의존하는 배포를 진행하지 않는다.
7. **기술 출시:** 위 조건을 충족한 운영 DB v22를 적용하고, 일반 `origin/master` push 및 BE·FE 합동 릴리스 후 실제 응답을 확인한다. Cloudflare 답변은 이 기술 릴리스의 선행 조건이 아니다. `ready=false`, `POLICY_SIGNUP_ENABLED=OFF`, `UPLOAD_POLICY_REQUIRED=OFF`를 유지해 미확정 정책을 공표하거나 필수 확인을 활성화하지 않는다.
8. **정책 최종 검토:** 공급자별 실제 국외 처리 경로·국가와 적용 법적 근거·고지 범위를 확인한 뒤 정책 공표 및 필수 확인 활성화 여부를 별도로 결정한다. 한국 전용 저장이라고 추정하지 않는다.

### 남은 순서

1. 승인된 범위의 운영 읽기 전용 백업·소유 로컬 복원·기존 기록 보존 검증, DB v22 적용, Fly BE v64 배포와 운영 HTTP·CORS·시작 로그 검증은 완료됐다. 아직 수행하지 않은 일반 push·FE 배포의 라이브 번들을 검증한다. FE 검증 전에는 기술 릴리스 전체를 완료로 기록하지 않는다.
2. 국외 이전 사실과 법적 근거·고지 범위를 추후 확인한다. Cloudflare 문의 초안은 필요할 때 참고할 수 있으나 이번 기술 릴리스의 필수 단계가 아니다.
3. 확인된 사실로 최종 개인정보처리방침·약관·업로드 안내를 작성·검토하고, 그 뒤 공표와 필수 확인 활성화 범위를 별도로 결정한다. 확인 전에는 정책 플래그를 비활성으로 유지한다.

검증은 실제 사용자 행동·권한 경계에 집중한다. 미확인 시작 차단, 잘못된 버전 거부, 다른 계정·밴드 확인 재사용 거부, 묶음 변경·공개 확대 재확인, 전송/완료 재시도, 기존 capability 유지, 삭제 요청 후 접근 제한 등 중요한 회귀를 우선한다. 단순 문구와 구현 구조를 그대로 복제하는 테스트는 늘리지 않는다.

## 8. 이번 범위에서 제외

- 권리자의 복잡한 전자서명·전원 동의 수집 시스템, 모든 회원의 신분증·전체 생년월일 수집.
- 업로드 내용의 자동 저작권 판정·얼굴 식별, 신고 접수 즉시 모든 경우에 적용하는 자동 삭제.
- 계정 자동 삭제·기존 영상 일괄 삭제·일괄 비공개 전환·R2 재변환.
- 설치형 앱·유료 서비스·후원 수취·홍보 사용·콘텐츠 재판매·AI 학습.
- 미확정 정책의 공표, 활성화 설정·비밀 설정 변경, 이번에 승인된 빈 제한 테이블·인덱스 외 운영 DB 변경, 실제 메일 발송.

## 9. 참고 근거와 한계

아래는 직전 정책 검토에서 사용한 공식 참고 자료다. 이 문서 작성 중 추가 법률 조사는 하지 않았다. 실제 공표 전에는 시행 중인 법률과 해당 처리 근거·신고 절차를 다시 확인한다.

- [개인정보보호위원회 안내](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS074&mCode=C020010000&nttId=11349): 필요한 개인정보 처리의 근거·고지를 포괄 동의와 구분하는 검토 참고.
- [개인정보 보호법 제36조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029335317): 정정·삭제 요청 검토 참고. 모든 요청의 처리 근거나 절차를 이 조항 하나로 설명하지 않는다.
- [저작권법 제46조](https://law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0046&lsiSeq=283335&urlMode=lsScJoRltInfoR): 이용허락 범위 검토 참고.
- [저작권법 제103조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1033064063): 복제·전송 중단과 재개 절차 검토 참고.
- [저작권법 사적 복제 조항](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1033063043): 멤버 전용 서비스의 이용이 예외에 해당하는지 검토할 때 참고.
- [민법 제5조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1026990807): 미성년자의 법률행위와 법정대리인 동의 검토 참고.
- [촬영·공표 동의 범위에 관한 대법원 판례](https://www.law.go.kr/LSW/precInfoP.do?precSeq=217373): 촬영 허락과 게시·공개 범위 구분 검토 참고.

법적 의무와 서비스 선택을 구분한다. 별도 체크박스 하나, 무료 운영, 약관 조항 또는 이용자의 확인 기록만으로 모든 개인정보·초상권·저작권 문제가 해결됐다고 설명하지 않는다.
