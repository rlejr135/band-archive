# 24시간 초대 링크 — 로컬 검증·운영 반영 승인 자료

작성일: 2026-10-19. 갱신: 2026-10-20. 상태: **초대 링크·가입 이름 필수 로컬 구현과 최종 전체 검증 완료. 운영 DB 변경·push·배포는 하지 않았으며 rev20·21 적용 승인을 기다린다.**

## 구현 범위

- 관리자(owner/admin)가 24시간 재사용 초대 링크를 발급·목록 조회·폐기한다. 발급 직후에만 원문을 보여 준다.
- 초대받은 사람은 공통 밴드 소개를 보고 로그인/회원가입·이메일 확인·필요한 정책 확인 후 명시적으로 가입한다.
- 가입은 기존 다른 밴드 가입을 유지하며 멤버 프로필을 정확히 하나 보장한다. pending/left/rejected는 일반 member가 되고 과거 admin 권한은 복구하지 않는다.
- 토큰은 fragment에서 즉시 제거하고 API body로만 보낸다. 서버에는 해시만 보관한다. 인증 복귀 식별자는 독립 난수이며 확인된 계정 이메일과 바인딩한다.
- 비공개 밴드는 가입 전 이름·소개 외 멤버 콘텐츠/미디어 URL을 노출하지 않는다.
- 기존 초대 코드 입력·발급·가입 경로는 종료하고 HTTP 410을 반환한다. 기존 DB 기록은 삭제하지 않는다.
- 일반 가입 요청을 소개 페이지로 옮기는 마지막 단계는 아직 포함하지 않았다.
- 2026-10-20 추가 요청: 일반 가입 신청과 초대 가입 확정에서 이름을 필수로 받고 새 멤버 프로필의 이름으로 사용한다. 기존 연결 프로필은 보존하며, 대기 신청 이름 보관을 위한 rev21 nullable 열 추가도 로컬 구현·검증 후 별도 승인받는다.

### 리뷰·테스트에서 보완한 사항

- 새 DB head 고정 테스트값 및 SQLAlchemy 과거 metadata의 컬럼 포함 검사 호환성.
- 정책 gate의 익명 예외를 미리보기·복귀 기록 발급 두 경로로 한정.
- 요청 제한 429 이후 실제 DB 작업 중단, 과도한 subject 메모리 증가 차단.
- SQLite 시각의 UTC offset 정규화, 가입·폐기 잠금 순서와 비회원 404 응답 차이 보완.
- 이메일 콜백이 Supabase 인증 파라미터를 지우지 않도록 처리.
- 새 초대·계정 전환 시 지연 응답 차단, 저장소 복원 시 만료 시각 복원, 로그아웃·인증 폼 이탈 시 지연된 복귀 기록 응답 무효화.
- 이름의 제어 문자·비가시 형식 문자·고립 surrogate 차단, 기존 연결 프로필 이름 보존, 신청 이름의 일반 명단/공개 응답 노출 방지.
- 동일 계정의 다른 초대 컨텍스트로 전환할 때 늦은 수락 응답의 이동·상태 갱신을 차단하고, 취소된 이전 요청이 새 폼을 영구 대기 상태로 만들지 않도록 분리.

## 운영 DB에 제안하는 변경 — 아직 미승인

현재 운영 rev19에서 rev20을 거쳐 rev21로 이동한다. 사전 확인에서 운영 revision이 달라졌으면 중단하고 다시 비교한다.

| 대상 | 추가 내용 |
| --- | --- |
| `band_invite_link` | 초대 해시, 밴드, 발급/폐기 사용자, 발급·만료·폐기 시각 |
| `invite_resume_context` | 복귀 해시, 초대 참조, 예상 이메일 HMAC, 생성·만료·계정 연결·완료 시각 |
| `band_membership.requested_name` | nullable `varchar(100)` 열 하나. 기존 행은 NULL이며 계정/프로필 이름 일괄 변경·backfill 없음 |
| 제약 | PK·해시 유일성·외래 키·양수 수명·계정 연결 상태 일관성 |
| 인덱스 | 밴드별 발급 목록과 유효한 복귀 기록 조회용 |
| 보안 | 두 테이블 RLS 활성화, 브라우저 정책 없음, PUBLIC/anon/authenticated 및 상속된 접근 권한 차단 |

- 새 테이블 두 개는 빈 상태로 추가하고 기존 멤버십에는 NULL 이름 열만 추가한다. 기존 행의 값·계정·프로필·콘텐츠·초대 코드·R2 객체는 변경하지 않는다.
- PostgreSQL이 만드는 새 테이블 시퀀스도 브라우저 접근을 차단한다.
- 기존 밴드·멤버십 테이블은 migration 트랜잭션 중 잠금 때문에 읽기·가입·설정 변경 등이 잠시 대기할 수 있다.
- 배포 후 정상 기능 사용 시 새 초대·복귀·감사 기록이 생성된다. 만료된 **새 복귀 기록만** 같은 밴드의 다음 복귀 발급 때 최대 100개씩 정리한다. 기존 초대 기록이나 감사 기록은 이 정리 대상이 아니다.
- 기존 콘텐츠 조회·작성 데이터 구조를 이전하거나 R2를 복사/삭제/재변환하지 않는다.

## 승인 후 시행할 안전 절차

1. 운영 rev19와 예상 스키마/권한을 읽기 전용으로 다시 확인한다. 다른 변경이 있으면 중단한다.
2. 같은 일관된 snapshot의 운영 DB 백업과 앱 public schema 백업을 비공개 로컬 경로에 보관한다. 자격 증명과 원문 개인정보를 로그·Git에 넣지 않는다.
3. 소유한 로컬 PostgreSQL에서 public 백업 복구, 데이터·관계·권한 보존 및 rev19→20→21 변경을 검증한다. 이 검증은 Supabase Auth 서비스 자체의 재해 복구를 주장하는 것이 아니다.
4. 검증 성공 시에만 운영 트랜잭션으로 rev21까지 적용한다. 실패·드리프트가 있으면 중단하고 보고하며 자동 우회/강제 rollback을 하지 않는다.
5. 기존 테이블의 행·관계·객체 키 보존, 새 테이블 빈 상태·기존 신청 이름 NULL, RLS/권한과 revision을 새 읽기 전용 연결로 확인한다.
6. BE→FE 순서로 배포하고 HTTP/CORS/로그·라이브 번들을 확인한다. DB 변경 전에는 새 스키마를 요구하는 BE나 초대 UI를 운영에 노출하지 않는다.

별도 승인 범위에 메일 발송 활성화, 인증 제공자 설정 변경, R2 삭제, 재변환, 스케일 변경은 포함하지 않는다. 실제 사용자 회원가입→확인 메일 왕복 검증은 사용자와 테스트 범위를 합의한 뒤 한다.

## 이번에 필요한 사용자 승인

위 백업·로컬 복구·보존 검증이 성공한 경우에만 운영 DB에 빈 초대 테이블 두 개와 신청 이름 nullable 열 하나(rev20·21)를 추가하고 BE→FE 배포까지 진행할지 확인받는다. 기존 프로필을 재명명하거나 데이터를 이전/삭제하는 승인이 아니다. 일반 가입 요청을 소개 페이지로 옮기는 마지막 화면 개편은 다음 단계로 남아 있다.

## 남는 한계

- Supabase 현재 공개 구현상 같은 Site URL origin의 query 콜백은 허용될 것으로 판단하지만, 운영 제공자의 실제 버전·메일 템플릿 왕복은 아직 확인하지 않았다. 복귀가 불가능하면 원래 초대 링크를 다시 열도록 안내한다. 필요한 설정 변경은 별도 확인한다.
- 프로세스별 요청 예산은 여러 worker/재시작에 걸친 전역 제한이 아니다. DB의 링크·밴드별 동시 복귀 상한은 실제 밴드 행 잠금으로 보장한다.
- 집중 경쟁 테스트는 가입/폐기/한도이며 모든 밴드 폐쇄·계정 운영 경쟁의 조합을 검증했다고 주장하지 않는다.

## 2026-10-20 읽기 전용 Supabase Advisor 확인

새로 제공된 Supabase 검토 지침에 따라 현재 프로젝트의 security advisor 결과만 읽었다. SQL 실행·DDL·설정 변경·개인정보 조회는 하지 않았다. 다음 항목은 이번 변경 때문에 새로 발생했다고 확인된 취약점이 아니며 별도 검토 권고다.

- INFO 35건: RLS 활성화·정책 없음. 이 앱은 브라우저 Data API 권한을 차단하고 Flask에서만 접근하는 계약이므로 정책을 무작정 추가하지 않는다. [공식 항목 설명](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy).
- WARN 1건: 기존 `public.audit_event_append_only` 함수의 search_path가 고정되지 않음. 함수 본문·호출 권한·실제 악용 가능성을 추가 검토해야 하며 이번에 변경하지 않는다. [공식 권고](https://supabase.com/docs/guides/database/database-linter?lint=0011_function_search_path_mutable).
- WARN 1건: 유출 비밀번호 보호 비활성화 안내. 적용 가능 플랜·영향·설정을 확인한 뒤 별도 운영 설정 승인을 받아 검토할 항목이다. 이번에 활성화하지 않는다. [공식 비밀번호 보안 안내](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).
