## 실행 상태 (2026-10-14)

- 보안 의존성: Flask-CORS 6.0.2 / Vite 7.3.7로 로컬 구현·커밋 완료. 운영 반영 전이다.
- 장소검색: 기존 공개 API에 입력/호출량/동시성/캐시/응답 크기/timeout/redirect 보호 구현·커밋 완료. 활성 멤버 전용 API 전환은 미결정이며 공개 소비자를 임의로 중단하지 않았다.
- CORS·장소검색·인증 관련 격리 회귀 테스트 55개, 전체 BE 회귀 667개 통과. 운영 반영 전이며 법적 적합성이나 모든 취약점 해소를 의미하지 않는다.
- 원본 감사 보고서는 당시 기준 그대로 보존한다. 아래 정책·고지 사실 확인 과제는 미완료이며 자동 발행하지 않았다.

## 이번에 먼저 진행할 두 작업 묶음

1. **보안 의존성 보완:** Flask-CORS와 Vite의 공식 공지 대상 버전을 수정 릴리스로 갱신한다. BE와 FE 커밋은 나눈다. PyJWT는 이번에 무조건 함께 올리지 않고 도달성과 호환성 검토 후 후속으로 둔다.
   - 선정 이유: 알려진 공지와 연결된 의존성이고 수정 경계·검증 방법이 명확하다. 다만 버전 영향 범위와 실제 앱에서의 악용 가능성은 구분한다.
   - Flask-CORS: 4.0.0 고정을 수정된 지원 버전으로 검토한다. allowlist·credentials·preflight·경로 정규화 회귀를 확인한다. 구체적인 고정 버전은 구현 시작 시 공식 공지/릴리스와 Flask 호환성을 재검증해 결정한다.
   - Vite: lockfile 7.3.1을 수정된 7.x(보고서 및 공식 공지 기준 7.3.7 이상)로 검토한다. Node/React/Capacitor 호환성을 보존하고 불필요한 메이저 업그레이드는 제외한다. 정적 운영 웹 자체에 개발 서버 취약점이 존재한다고 단정하지 않는다.
   - 근거: [Vite maintainer advisory](https://github.com/vitejs/vite/security/advisories/GHSA-rq7h-c2jc-7f22), [Flask-CORS GitHub Reviewed Advisory](https://github.com/advisories/GHSA-8vgw-p6qm-5gr7). 다른 공지와 앱 도달성은 원본 보고서 참조.
2. **공개 장소검색 API 남용 방지:** `/api/search-places`의 입력 상한·호출량/동시 실행 제한·캐시와 upstream 실패 처리를 보완한다.
   - 선정 이유: 실제 등록된 공개 경로가 외부 Naver API와 단일 BE worker를 사용한다. 현재 코드에 호출량 제한과 캐시가 없고 입력 길이 상한도 없어 서비스 가용성과 제공자 쿼터를 소모할 수 있다. 쿼터·과금의 실제 영향은 공급자 설정에 따라 다르다.
   - 인증 정책: 장소검색은 쓰기 폼의 기능이므로 실제 v2 호출자를 확인한 뒤 활성 밴드 멤버 대상의 band-scoped 경로를 우선 설계한다. 기존 공개 경로를 계속 제공해야 하는지 명시적으로 결정하며, 보호된 새 API를 두고 무제한 구 경로를 남기지 않는다.
   - 클라이언트 debounce는 UX/호출 절약일 뿐 서버 보안을 대체하지 않는다. 신뢰할 proxy/IP 정책과 제한 저장소를 함께 설계한다. 현재 단일 worker용 메모리 제어의 재시작/다중 worker 한계를 명시하고, 향후 k3s에서는 공유 제한 저장소 또는 ingress 제한으로 전환한다.

## 보안 후속 과제

| 항목 | 상태 / 우선순위 | 다음 판단 |
|---|---|---|
| 레거시 v1 쓰기 fail-closed | 다음 보강. 직전 운영 값 false 확인; 현재 공개 쓰기 노출로 분류하지 않음 | production 기본값/시작 검증과 배포 계약에 고정. 개발·테스트 레거시 opt-in 유지 |
| PyJWT 갱신 | 후속. 원본 보고서에서 현재 key.key 호출의 인증 우회는 입증되지 않음 | 공지별 영향 함수/수정 버전 구분, JWT/JWKS 회귀 후 최소 갱신 |
| 공개 GET 페이지 상한·레이트 제한 | 후속 | 실제 레거시 호출과 edge/앱 제한 요구 조사 |
| MIME·CSP·전달 헤더 | 후속 방어 보강 | 저장 origin·헤더 실제 확인. 영상/음원 inline 재생 보존, attachment 일괄 적용 금지 |

## 정책·고지 과제: 대시보드 작업과 별도 진행

| 항목 | 상태 | 선행 확인 / 최소 방향 |
|---|---|---|
| 개인정보처리방침·가입/로그인 링크 | 출시 준비상 우선 과제이나 사실 확인 필요 | 처리자 명칭/연락처, 실제 항목·목적·처리 근거·보유기간 확정 후 문서 작성·노출 |
| 국외 처리·수탁 고지 | 사실 확인 대기 | 확인된 DB Tokyo / 앱 NRT와 미확정 Auth·SMTP·R2 경로를 분리. 공급자 계약·국가·기간을 추측하지 않음 |
| 만 14세 이상 정책 | 설계 대기 | 최소 연령 확인과 미달 처리 선택. 생년월일 전체 수집이나 모든 이용자의 별도 동의를 자동 추가하지 않음 |
| 계정 삭제·익명화·보존 | 정책 결정 대기 | Auth/로컬 사용자/소유권/멤버십/기여물/감사 로그/백업 처리 규칙부터 확정 |
| 공개 업로드·권리·신고 안내 | 별도 과제 | PUBLIC/MEMBERS 설명, 업로드 권한·신고/삭제 절차. 개인정보 동의와 저작권 규칙을 혼합하지 않음 |

위 항목을 미루어도 법적 문제가 없다고 판단한 것은 아니다. 필요한 운영 사실을 받아 법적 근거·고지를 먼저 확정한다. 단순 로그인에 포괄 필수동의 checkbox를 넣는 방식은 우선안이 아니다. 상세 근거와 한계는 원본 고지 보고서를 따른다.
