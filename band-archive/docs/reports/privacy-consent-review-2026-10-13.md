## 요약

가입은 이메일·비밀번호를 받고 이메일 확인을 요구하지만, 가입 화면에는 개인정보 처리방침이나 수집·이용 관련 고지가 확인되지 않는다. 검색된 웹 앱 소스와 API 라우트에서 계정 탈퇴·계정 삭제 기능도 찾지 못했다. AppUser의 이메일과 Supabase subject를 로컬 DB에 동기화한다. 따라서 우선 처리할 일은 가입 시 포괄적인 “필수 개인정보 동의” 체크박스를 추가하는 것이 아니라, 실제 처리 현황과 법적 근거를 확정하고 한국어 개인정보 처리방침을 작성해 쉽게 열람하도록 하는 것이다.

개인정보 보호법상 계약 체결·이행에 필요한 계정 정보는 동의가 아닌 법 제15조 제1항 제4호를 근거로 처리할 수 있다. 개인정보위도 서비스 가입에 필요한 정보에 형식적인 필수 동의를 요구하지 말라고 안내한다. 계약과 무관한 선택 처리를 도입할 때에만 목적별 별도 동의를 검토한다. 국외 이전은 단일한 “무조건 동의” 절차로 처리하지 말고, 법 제28조의8상 실제 이전 경로에 맞는 근거와 고지 항목을 먼저 확정해야 한다.

## 법적 기준: 고지, 법적 근거, 동의는 구분

### 법에서 요구되는 사항

1. **처리방침 공개:** 개인정보 보호법 제30조는 개인정보 처리방침을 수립·공개하도록 한다. 회원서비스 운영 항목, 처리하는 개인정보와 보유기간, 정보주체 권리 행사, 파기, 안전조치, 책임자/고충처리 연락 등을 실제 운영에 맞게 기재한다. 가입 화면 또는 로그인 영역에서 쉽게 접근할 수 있게 한다. 세부 기재방식은 개인정보위의 2025-04-21 처리방침 작성지침 개정 공개 자료를 참고한다.
2. **필요한 최소처리와 파기:** 목적 달성에 필요한 범위만 처리하고, 보유기간이 지났거나 목적이 끝나 개인정보가 불필요해지면 다른 법령상 보존 의무가 없는 한 지체 없이 파기한다(법 제21조). “계정 탈퇴 즉시 모든 감사 로그와 다른 이용자가 만든 콘텐츠까지 항상 전부 삭제”라는 일률적 결론은 법 조문만으로 낼 수 없다. 각 자료별 목적·보존근거와 타인의 권리를 확인해야 한다.
3. **만 14세 미만 처리:** 동의에 근거하여 만 14세 미만 아동 개인정보를 처리한다면 법정대리인의 동의 및 그 확인이 필요하다(제22조의2). 이는 만 14세 이상 이용자에게 연령 확인 checkbox를 일률적으로 요구한다는 뜻은 아니다.
4. **국외 이전:** 운영자가 확인한 Supabase 프로젝트/PostgreSQL DB Tokyo와 Fly NRT 앱의 각 처리 경로에 대해 개인정보 국외 처리·위탁·보관 여부를 확인해야 한다. 이 사실은 Supabase Auth/SMTP의 처리 국가까지 확정하지 않는다. 제28조의8은 여러 이전 근거를 두며, 계약 이행상 필요한 위탁·보관의 경우 법정 요건 아래 정보주체에게 제2항 사항을 알리는 경로가 있다. 따라서 모든 경우에 별도의 국외이전 동의를 일괄 체크시켜야 한다고 권고하지 않는다. 실제 근거를 선택하고 해당 경로의 고지 요건, 수탁 관계, 이전 정보·국가·시기·방법·목적·보유기간·거부권과 불이익 등 적용 항목을 운영 계약과 함께 확정한다.

### 계약상 필요 처리와 동의

이메일은 계정 생성·이메일 확인·인증·암호 재설정에 필요할 수 있으며, Supabase UUID는 인증된 사용자를 로컬 권한 모델과 연결하는 데 쓰인다. 목적에 필요한 범위라는 전제 아래 제15조 제1항 제4호(계약 체결·이행 또는 계약 체결 과정에서 요청된 조치)를 법적 근거로 검토할 수 있다. 근거와 최소 필요성을 처리방침에 설명한다. 개인정보위는 서비스 가입처럼 계약 이행에 필요한 정보에 동의를 요구할 필요가 없다고 명시하며, 동의가 필요한 계약 외 목적은 자유로운 선택을 보장하라고 안내한다. 광고/마케팅, 선택 프로필 공개 등 코드에서 확인되지 않은 목적을 당연히 있다고 가정하지 않는다.

### 권장되는 설계·운영 사항 (법정 의무 및 동의와 구분)

- 가입 및 로그인 화면에 처리방침 링크와 수집되는 계정정보의 핵심 내용을 눈에 띄게 두고, 처리방침 본문은 항목·목적·근거·기간을 이해 가능한 문장으로 설명한다.
- 서비스 정책으로 가입 대상을 만 14세 이상으로 제한한다면 “만 14세 이상” 최소 확인과 미달 시 가입 중단을 설계하는 방안을 검토한다. 이는 이 서비스의 연령 제한 정책을 집행하기 위한 권고이지, 모든 14세 이상 서비스에 부과되는 별도 checkbox 의무라고 단정하지 않는다. 생년월일 전체 수집은 필요성과 보유기간을 별도 검토한다.
- 계정 삭제 접점과 요청 처리 프로세스를 제공한다. Supabase Auth 계정, 로컬 AppUser, 멤버십/기여 기록, public uploads/파일, audit event, 백업에 대해 결과를 데이터 종류별로 정의하고 처리방침에 알린다. 법정 보존 사유가 있는 데이터는 별도 분리 보관·접근 제한을 검토한다.
- 공개 업로드 전 PUBLIC 여부, 게시물·음성·영상·프로필이 누구에게 보이는지, 비회원 공개 및 URL 재공유 가능성을 분명히 안내한다. 저작권 관련 이용약관에는 사용자가 업로드·공개할 권한이 있는지 확인하도록 하고, 공개 목적에 필요한 범위의 서비스 운영 허락, 침해 신고·삭제 절차, 계정 종료 시 콘텐츠 선택을 다룬다. 개인정보 동의 체크박스에 저작권 허락을 합치지 않는다.
- 선택적인 별도 개인정보 처리가 생길 경우에만 항목·목적별로 동의를 분리하고, 거부해도 기본 계정 기능을 쓸 수 있는지와 실제 불이익을 설명한다.

## 최소 수정 권고

1. **운영 사실 확정:** 사업자/개인정보처리자 명칭과 연락처, 회원 계정의 실제 처리 항목·목적·근거·보유기간, Supabase 프로젝트/PostgreSQL DB Tokyo와 Fly NRT 앱의 역할 및 처리 위치, Supabase Auth/SMTP의 처리 국가·이메일 전송·하위수탁자, Supabase DB 백업 및 Fly 앱 로그의 삭제/보존 정책을 각각 확인한다. R2 제공자·버킷 위치·하위수탁·보존은 실제 설정/계약으로 확인하기 전까지 보고서 또는 정책에 특정하지 않는다.
2. **한국어 처리방침 게시:** 확정 사실로 법 제30조에 맞는 처리방침을 작성하고 가입 전에 쉽게 접근 가능하게 연결한다. 공란을 추측으로 채우지 않는다. 이용약관은 실제 계정·업로드 기능의 권리와 공개 규칙을 확정한 뒤 별도 작성한다.
3. **가입 UX 최소 보완:** 가입 폼 옆에 처리방침 링크와 계정 처리 핵심 고지를 둔다. 계약 수행의 필수정보에는 동의 checkbox를 요구하지 않는다. 선택 목적이 실제 도입된 경우에만 분리 동의 UI와 기록을 추가한다. 연령 확인은 운영자가 선택한 만 14세 이상 정책에 따라 최소 수집으로 설계한다.
4. **삭제 설계 후 구현:** 데이터 항목별 계정 종료 흐름, Supabase/로컬 계정 연동, 타 밴드의 콘텐츠 권한, 파일 삭제, 감사 로그의 최소 식별화/보존과 법정 예외를 설계·검토한 다음 계정 삭제 기능을 구현한다. 정책·운영 근거가 확정되기 전에 즉시 cascade 삭제를 구현하지 않는다.

### 대안과 트레이드오프

- **서비스 정책상 만 14세 이상만 허용:** 만 14세 미만 가입을 차단할 최소 확인을 검토한다. 이는 서비스의 선택한 연령 제한을 집행하기 위한 설계안이다. 생년월일 수집을 추가할 때는 별도 필요성·보유기간·파기 판단이 필요하다.
- **국외 이전 요건을 아직 확인할 수 없음:** 추측으로 고지·동의문을 만들지 말고 공급자 계약/설정과 이전 세부사항을 확인한다. 합법적인 처리 경로를 입증할 수 없으면 해당 서비스의 개인정보 전송 기능을 출시하지 않거나, 국내 처리 등 현실적인 대안을 검토한다.
- **계정 삭제의 콘텐츠 귀속을 결정할 수 없음:** 유예/관리자 검토 등 임시 요청 처리 절차를 만들고 보유 사실을 투명하게 고지하되, 요청을 무기한 미처리하는 체계를 정상 대안으로 보지 않는다. 삭제 범위와 다른 이용자 권리 사이의 정책 결정을 먼저 내린다.

## 검증 및 운영자 확인 질문

이 보고서는 파일/검색 결과와 공식 원문 페이지를 대조한 정적 점검이다. 실행 테스트, 실제 UI 브라우징, 외부 운영 설정·계약·데이터베이스 열람은 하지 않았다. 동일한 HEAD의 가입 코드에서 연령·동의/처리방침 UI 부재, 로컬 사용자 모델·동기화 로직, 인증 라우트와 전체 프론트 소스에서의 계정 삭제 기능 부재를 확인했다. 저장소 파일이 실제 배포와 동일한지, 별도 웹 정책 페이지가 있는지는 별도 검증이 필요하다.

운영자가 답해야 할 질문:

1. 개인정보처리자는 누구이며, 정보주체가 열람·삭제 요청을 보낼 실제 연락처와 처리 담당자는 무엇인가?
2. Supabase Auth에서 이메일/인증 메타데이터가 실제 어느 국가에서 처리되고 어떤 기간 유지되는가? Tokyo 외 처리 또는 지원 인력의 원격 조회가 있는가? 이메일 발송/SMTP와 하위수탁 관계 및 국외 이전 세부사항은 계약에 어떻게 적혀 있는가?
3. Supabase PostgreSQL DB와 백업은 어디에 얼마 동안 보관되는가? Fly NRT 앱 로그는 무엇을 담고 얼마 동안 보관되는가? 삭제된 계정의 DB 백업 만료까지 처리와 접근 통제는 무엇인가?
4. R2 또는 실제 object storage가 무엇이며, bucket의 jurisdiction/location, public access 및 CDN/URL 전달, 하위수탁자, 저장·삭제·백업 수명은 계약과 설정상 어떻게 정해져 있는가?
5. 가입/이메일 인증과 서비스 운영 외에 현재 실제 수집하는 분석·로그·쿠키·광고 데이터가 있는가? 없다면 도입하지 않은 선택 처리 목적을 정책에 쓰지 않는다.
6. 만 14세 미만을 어떻게 차단할 것인가? 생년월일을 수집할 필요가 있는가, 아니면 저장 전 연령 assertion 방식으로 충분한가?
7. 계정 삭제 시 밴드 멤버십, 사용자가 올린 연습 음원·영상·이미지, 댓글/추천, 다른 멤버가 소유한 공유 콘텐츠, `audit_event.details_json`, 백업을 각각 어떻게 처리할 것인가? 법령상 보존 대상과 근거가 실제로 있는가?
8. 공개 업로드된 개인의 음성·영상·이름이 비회원에게 보이는 것을 사용자에게 어떤 시점과 방법으로 알리고, 저작권 침해 신고/삭제 요청은 누가 처리할 것인가?

## 법령·공식 안내

- [개인정보 보호법 제22조의2(만 14세 미만 아동)](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1020398521)

- [개인정보위, 개인정보 처리방침 작성지침 개정본 공개(2025-04-21)](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS074&mCode=C020010000&nttId=11133): 제30조 처리방침 공개, 동의 없이 처리하는 회원서비스 운영 정보와 동의 필요 항목을 구분하고, 가입/로그인 메뉴에서 쉽게 접근하도록 한 내용.

## 메인 에이전트 우선순위 작업 지시안

1. 운영자로부터 위 질문 1-5의 처리자 정보, 실제 개인정보 흐름, 업체 계약·국가·보유기간을 받아 사실표를 확정한다. 미확정 R2/수탁자 정보를 추측해 정책을 쓰지 않는다.
2. 그 사실표를 바탕으로 처리방침 초안을 만들고 제15조 처리근거, 제21조 보존/파기, 제28조의8 국외 이전 경로·고지, 제30조 필수 공개 항목을 별도 법률 검토한다.
3. 승인된 처리방침을 구현하고, 가입 UX에서 처리방침 핵심 고지/접근 링크만 먼저 적용한다. 필수 개인정보 동의 checkbox는 법적 근거가 동의인 별도 처리가 확인된 경우에만 분리 추가한다.
4. 운영자가 만 14세 이상만 허용하는 정책을 택한 경우에만 그 정책을 집행할 최소 연령 확인을 설계한다. 이후 계정 탈퇴/삭제 및 콘텐츠·파일·감사 로그 처리 규칙을 설계한다. 본 보고서는 어느 것도 자동 승인하거나 구현 승인한 문서가 아니다.
