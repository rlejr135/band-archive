## 점검 방식과 판단

정적 소스 및 공식 보안 공지·법령 검토다. 운영 공격 테스트, 실제 이용자 정보 조회, 신규 테스트 실행, 코드 수정·커밋·push·배포는 수행하지 않았다. 권한 우회나 침해가 없다는 보증이 아니며, 버전 영향 범위와 앱의 실제 공격 조건은 별개다.

직전 운영 확인에서 v1 쓰기는 비활성화되어 있었다. 이를 현재 무인증 쓰기 노출로 분류하지 않는다. 운영 웹은 Cloudflare의 정적 번들이므로 Vite 개발 서버의 취약점을 운영 웹 자체의 파일 유출로 해석하지 않는다. Supabase PostgreSQL은 Tokyo, Flask 앱은 Fly NRT이며, Auth·SMTP·R2 처리 국가/계약/보유기간은 추가 확인 사항이다.

## 후속 담당자에게 전달할 순서

| 순서 | 담당 | 권고 작업 | 완료 검증 / 선행 조건 |
|---|---|---|---|
| 1 | BE 개발 | Flask-CORS 등 보안 공지 대상 의존성의 수정 릴리스·호환성을 확인하고 최소 범위로 갱신한다. PyJWT는 현재 호출 방식의 도달성과 다른 공지도 분리 검토한다. | 허용/거부 origin, credentials, preflight·경로 매칭, JWT 거부·키 교체 회귀 테스트와 전체 BE 테스트. |
| 2 | FE 개발 | Vite의 수정된 7.x 릴리스(보고서 기준 7.3.7 이상)를 검토하고 lockfile을 함께 갱신한다. 개발 서버 외부 공개 여부도 확인한다. | 전체 FE 테스트·lint 변경분·운영 build, 개발 서버 네트워크 경계. Windows에서 적용되지 않는 개별 공지 조건은 분리한다. |
| 3 | BE / 운영 | 공개 장소검색 프록시에 입력 길이 상한, 호출량·동시 요청 한도, 캐시, upstream timeout 및 제공자 쿼터 알림을 설계한다. | 외부 Naver 호출을 mock한 정상 요청/한도 초과/캐시/timeout 테스트. 실제 사용 흐름과 신뢰할 프록시 IP 정책 확인. |
| 4 | BE / 릴리스 | production 레거시 쓰기가 설정 누락으로 재활성화되지 않도록 fail-closed 기본값 또는 시작 검증을 설계한다. | 개발·테스트 호환성은 명시적 opt-in으로 유지. production 설정 누락 및 모든 v1 변경 요청 차단 계약 검증. |
| 병행 A | 운영자 + 고지 담당 | 처리자 이름·실제 연락처, 수집 목적·항목·기간, Auth/SMTP/R2 수탁·국외 처리 사실, DB 백업·로그 보유 정책을 먼저 확정한다. | 공급자 계약/설정과 실제 서비스 처리 흐름으로 확인. 비밀값은 보고서에 기록하지 않는다. |
| 병행 B | 고지 담당 + FE | 사실 확정 후 최소 개인정보처리방침 초안과 가입·로그인 접근 링크를 준비한다. | 처리 근거·고지와 별도 동의를 구분하고, 사실 확인/필요한 전문 검토 후 적용한다. 무조건 필수동의 checkbox를 추가하지 않는다. |
| 후속 C | 정책 담당 + BE/FE | 선택한 만 14세 이상 정책의 최소 확인 절차와 계정 삭제·소유권 이전·기여물 익명화·보존 예외를 설계한다. | 운영자 정책 결정 후 Supabase Auth/로컬 DB/콘텐츠/감사 로그/백업 각각의 처리 결과와 권리행사 접점을 검증한다. |
| 후속 D | 업로드 / FE / 운영 | MIME 결정·콘텐츠 전달 헤더·CSP 등 방어 보강을 평가한다. | 영상·음원은 안전한 MIME과 격리된 origin에서 inline 재생을 유지한다. 모든 미디어에 attachment를 일괄 적용하지 않는다. 영상 재변환이나 운영 R2 변경은 별도 승인. |

법적 판단의 근거와 미확인 사항은 고지 담당 보고서에 있다. 계약상 필수 개인정보에 일괄 동의를 추가하는 방식은 우선안이 아니다. [개인정보위 필수동의 안내](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS074&mCode=C020010000&nttId=10566)를 참고하되 실제 처리 근거는 개별 확인한다.

## 실행 경계

이 대기열은 담당자의 수정 권고를 메인에게 전달한 기록이다. 현재 작업은 보고서 작성·접수까지이며, 구현 시작이나 운영 배포를 수행하지 않는다. 후속 구현을 요청받으면 안전하게 분할·테스트·단위 커밋하고 외부 push·배포 권한을 확인한다. 운영 개인정보 조회, 공급자 설정 변경, 운영 DB/R2 삭제, 높은 CPU의 영상 재변환은 자동 수행하지 않는다.

두 예약은 5일 간격, 한국 시간 09:00(보안) / 09:15(고지·동의)로 변경했다. 새 보완점이 생길 때만 날짜별 권고 보고서를 작성하고 메인에게 전달한다. 변경이 없는 동일 지적은 반복 보고하지 않는다. 로컬 보고서는 현재 docs ignore 정책에 따라 Git에 자동 포함되지 않는다.
