# 권리 요청·삭제·백업 정리 운영 절차 초안

작성일: 2026-10-21. 배포 전 검증 중인 내부 운영 초안이며 최종 국외 이전 고지 범위·법적 근거가 미확정이다. 현재 승인된 일반 삭제 기능을 재사용하는 방향이며, 이 문서로 R2 파일 삭제·원격 DB 쓰기·자동 메일 발송을 실행하지 않는다.

## 1. 접수와 최소 확인

- 비회원·탈퇴자·촬영된 사람도 중앙 CONTACT_EMAIL로 접수한다. 로그인·owner 동의·새 회원가입을 필수 접수 조건으로 두지 않는다.
- 대상 URL 또는 최소 식별 정보, 요청 종류·이유·원하는 조치, 답변 연락처를 받는다. 출연자·저작권자·대리인 등 관계를 필요한 만큼 확인한다.
- 모든 사람의 신분증·전체 생년월일을 일괄 요구하지 않는다. 자료가 더 필요하면 그 이유와 최소 범위를 안내한다.
- 비공개 접수 기록에 사건 식별자·접수일·유형·처리 상태·기한·최소 근거를 둔다. 공개 Git 문서에 실제 인물·개인 메일·신고 본문·토큰·서명 URL·파일키를 넣지 않는다.

## 2. 유형에 맞는 중단·검토·통지·재개

| 유형 | 처리 원칙 |
|---|---|
| 개인정보 열람·정정·삭제·처리정지 | 본인·대상 정보와 적용 근거를 확인하고 법정 기한·예외에 따라 처리·안내. 법적 거절·별도 보존 사유가 있으면 근거와 범위를 기록 |
| 저작권 복제·전송 중단 | 적법한 권리소명·요청 요건이 갖춰진 경우 지체 없는 중단 등 해당 법정 절차 적용. 게시자 통지·정당한 권리소명·재개 예정 통지와 법정 기간·소송 관련 조건을 확인하고 재개 |
| 사생활·초상·명예 등 게시물 침해 | 요청과 침해 사유를 확인하고 적용 법률상 삭제·반박·임시조치 및 통지 요건을 검토. 저작권 재개 절차를 그대로 복사하지 않음 |
| 단순 밴드 탈퇴·계정 삭제 | 탈퇴는 공동 기록 자동 삭제가 아님. 계정 삭제는 Auth·로컬 계정·소유권·개인 연결·공동 콘텐츠를 구분해 수동 처리. 권리 침해 신고와 같은 절차로 단순화하지 않음 |

문의·신고 처리 기록은 사건 종료 후 30일 이내 정리한다. 진행 중인 분쟁이나 법정 보존에 필요한 최소 자료는 목적·범위·기간과 접근 제한을 분리해 관리한다. 계정 삭제 시 감사 기록의 개인 연결은 제거하거나 익명화한다. 업로드 확인 기록은 해당 콘텐츠가 유지되는 동안 보존하고 삭제 확정 후 30일 이내 정리한다.

법정 즉시 중단 등이 필요한 요청은 일반 검토 대기나 owner 승인 때문에 지연하지 않는다. 긴급성·범위에 맞게 접근 또는 전송을 제한하고 요청자·게시자에게 필요한 통지와 이의제기 방법을 안내한다. 재개는 owner의 요청만으로 자동 처리하지 않고 해당 법률 요건·기간·통지를 충족한 뒤 판단한다.

모든 신고에 자동 삭제를 실행하지 않으며, 법정 절차를 “운영자가 편할 때 처리”하는 재량으로 대체하지 않는다. 세부 서류·법정 기한은 실행 당시 현행 조문으로 확인해 사건별 작업 목록에 적는다.

## 3. 콘텐츠·접근 경로 조치

- 일반 콘텐츠 삭제 권한은 owner/superadmin에 두되, 법정 권리 행사는 별도로 운영자가 검토·조치한다.
- 대상 원본·변환본·M4A·썸네일/대표사진·로고 등 참조·공유키를 확인하고 요청 범위에 필요한 조치를 정한다. 기존 지속성 삭제 작업의 권한·공유 참조·재시도 검증을 우회하지 않는다.
- 현 v2 서명 URL 상한은 공개 1시간, 멤버 전용 5분이다. 권한 제한 뒤에도 기존 링크가 만료까지 남을 수 있다. 긴급한 전송 중단은 재발급 차단만으로 충족되는지 확인하고 가능한 추가 제한을 판단한다.
- 성공·부분 실패·blocked 상태를 구분한다. 삭제 요청 접수나 작업 생성만으로 모든 파일 삭제 성공을 통지하지 않는다. 실제 처리 상태·공급자 잔존 범위를 안내한다.
- 복원 시 삭제·중단된 자료를 다시 서비스하지 않도록 삭제 확정 목록과 복원본을 대조한다.
- 미디어는 밴드 존속 중 기록 제공 목적에 따라 보관하고 정당한 요청·목적 종료 때 정리한다. R2의 확인된 7일 규칙은 **미완료 multipart abort**이며 완료된 영상·음원·사진의 자동 삭제 규칙으로 해석하지 않는다. 전역 기간 자동 삭제는 추가하지 않는다.

## 4. 운영자 DB 백업의 30일 이내 정리

사용자는 **삭제가 확정된 개인정보의 운영자 보관 DB 백업 잔존분을 삭제 확정 후 30일 이내 정리**하도록 승인했다. 자동 정리 기능은 아직 없으므로 운영자가 기한과 대상 목록을 관리하고 수동 실행·대조·증빙한다. 대량 로그 purge나 공급자 전역 삭제 자동화는 이번 범위가 아니다.

1. 삭제 확정일과 30일 이내 처리 기한을 비공개 사건 기록에 등록한다. 보존이 필요한 법적 예외가 있으면 목적·근거·범위·기간·접근 제한을 별도로 검토한다.
2. 운영자 PC·승인된 보관소에 둔 DB dump·SQLite snapshot·복원본·개인정보를 담은 증거 사본을 목록으로 확인한다. 파일 본문을 채팅·공개 보고서에 노출하지 않는다.
3. 개인정보가 남은 사본을 기한 내 안전하게 정리하거나 필요한 최소 자료만 남긴 정리본으로 대체한다. 복구 가능성·암호화·접근 통제와 삭제 대상의 정확성을 확인한다.
4. 파일명·개인정보 원문 없이 대상 수·범주·완료일·검증 결과의 최소 증빙을 남긴다. 기간 내 처리 불가 사유를 파악하면 기한 전에 해결 경로와 필요한 조치를 판단한다.
5. 공급자가 관리하는 백업·로그, 이용자가 별도로 받은 사본에는 이 30일 약속을 자동 확대하지 않는다. 공급자별 잔존·파기와 요청 경로는 별도 확정·안내한다.

운영 DB·R2에 대한 실제 조작은 구체적인 대상·기존 승인 범위를 확인하고 수행한다. 이 초안만 보고 실제 데이터를 지우거나 백업 파일을 일괄 제거하지 않는다.

## 5. 최종 운영 개시 게이트

- 중앙 연락처 접근권한·접수 확인·담당자·사건별 법정 기한 관리 수단 확정.
- 임시 제한·통지·이의제기·재개와 계정 수동 삭제의 실제 실행 가능성 검토.
- 공급자별 국외 이전 경로의 적용 법적 근거·국가·법정 고지 범위 확정. 확인된 Supabase Tokyo와 R2 APAC를 구분하고 APAC를 특정 국가로 기재하지 않음. Gmail이나 DPA 서명 여부만으로 사용 가능성을 단정하지 않음.
- 승인된 업로드 확인·계정 감사·문의 신고·운영자 백업의 보존 기준과 수동 정리 책임을 실제 운영 절차에 반영.
- 최종 약관·방침·업로드 UI와 적용 버전·시행일 승인. 자동 메일 발송은 별도 승인 전 활성화하지 않음.

공식 참고: [개인정보 보호법 제36조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029335317), [저작권법 제103조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1033064063). 각 조문 하나가 모든 유형의 요청 절차를 대신하지 않는다.
